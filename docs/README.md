## 三、归档策略（何时进 `docs/archive/`）

满足**任意两条**即归档：

1. **内容已被持续更新处完全沉淀**（如阶段报告的结论已写入模块 `CHANGELOG.md` / `AGENTS.md`）。
2. **时效性极强**：写的是「某一天的交付快照」（含当时的工作树状态、提交号、未提交清单），
   两周后即为噪声。
3. **日常检索不到它**：每天开工不会打开，只在写复盘 / 追责 / 找历史决策时才可能用。

归档规则：

- 用 `git mv` 迁移，**不改内容**（历史应当保持是历史的原样；确需更正请在文首加「归档后更正」说明）。
- 迁移后更新引用它的文档链接，并在原位置留**一行索引**（不放全文）。
- 归档文件内部的相对链接若指向仓库根，需相应加 `../../`。
- 需要找回时：`git log --diff-filter=D --name-only -- '*<文件名>'` 或直接看 `docs/archive/`。
