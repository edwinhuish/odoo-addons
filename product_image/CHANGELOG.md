## [19.0.2.4.0] - 2026-09-06（待验证）

### 变更

- **主图可参与拖动排序（序列首位即主图）**：此前主图固定首位且不可拖动。现任意图片（含主图）都可拖动；把某张图拖到首位即把它设为主图，把主图拖到后面则由上位图成为新主图。
- **排序写回改为「统一数组 + diff + 最小写回」**：前端把主图与图库合成同一个数组（`displayItems` / `displayKeys`，顺序即下标），后端仍分开存储（产品 `image_1920` 字段 + `product.image.gallery.sequence`），拖动后按数组 diff 分别写回：
  - `onManageReorder(after)`：以拖动前的 `displayKeys` 为 before 与 after 比对；长度不一致（期间发生增删）直接放弃，避免错位；
  - 首位仍是 `main` → 只重排图库（不碰主图字段）；
  - 首位是图库图且当前有主图 → `_writeOrderWithNewMain()`：读该图 base64（已保存记录可能只有 binary size，需 ORM 读）→ **先读原主图 base64**（必须在覆盖主图字段之前，否则读不到原图）→ 原主图落位新建为图库记录 → 新主图数据写入 `image_1920` 并删除其图库记录（**移动**，不复制、不重复展示）→ 新图库顺序 = after 去掉首位、`main` 处换成新建的原主图记录；主图变更后页面展示回到新的第一张；
  - 图库顺序统一由 `_writeGalleryOrder(galleryKeys)` 按 10 步长写入，且**逐项与当前 `sequence` 比对，只写位置真的变了的记录**（未变动的记录不产生任何写操作，避免无谓 dirty 与重排抖动）；
  - 无主图时（`keys` 不含 `main`）→ 仅重排图库，不凭空造主图。
- **附带修复：未保存图库记录无法定位**：`_gidFromKey` 此前只接受数字 id，而「原主图落位图库」新建的是未保存记录（key 形如 `gvirtual_1`），会导致后续再次拖动 / 删除该图静默失败；现兼容虚拟 id 字符串（与 `record.resId || record.id` 严格相等命中）。
- **修复「批量删除」进入勾选模式后没有任何操作按钮**：header 的勾选态分支误用 `<template t-if>`——`<template>` 是 HTML 惰性容器，其内容不会被渲染，于是只剩缩略图上的勾选圈，看不到「已选 N 张 / 删除 / 取消」。已改为 `<t t-if>`。
- **弹窗侧同步放开主图限制**：`_dragEnabled` 由「至少两张图库图」改为「至少两张图片」；插入位允许为 0（可拖到首位）；主图缩略图同样带 `o_gm-sortable`（grab 光标）；排序提交后改为按**落位索引**重拉列表（更换主图会让原 `main` key 指向另一张图，按旧 key 锚定会漂移）。

- 交互变化：① 主图可拖动，拖动改变首位会**更换产品主图**（随产品保存生效，为「移动」而非复制——被提升的图库记录会删除，原主图新建为图库记录）；② 勾选模式正常显示「已选 N 张 / 删除 / 取消」；③ 仅调整图库顺序（首位不变）时的行为与之前完全一致。

## [19.0.2.3.2] - 2026-09-06（待验证）

### 变更（修复：拖动排序布局）

- **根因修复——拖动瞬间缩略图出现巨大间隙并顶出横向滚动条**：模板中缩略图带 Bootstrap 工具类 `position-relative`，而 `.position-relative` 的定义是 `position: relative !important`（已核对 `web/static/lib/bootstrap/dist/css/bootstrap.css`），**压过**排序态 `.o_gallery_manage-grid.is-sorting .o_gallery_manage-tile { position: absolute }`。tile 因此始终留在流内，`transform: translate(col*76, row*76)` 叠加在流内位置之上，偏移量随序号累积 → 巨大间隙、横向溢出（`overflow-y:auto` 会让 `overflow-x` 的 `visible` 计算成 `auto`，于是出现横向滚动条），拖拽块也远离鼠标。
  - 缩略图不再使用 `position-relative` 工具类，常态定位改由 SCSS 的 `.o_gallery_manage-tile { position: relative; }` 提供（无 `!important`），排序态的 `absolute` 得以生效 → 拖动时缩略图保持原有 8px 间距、与原流内位置完全重合；
  - 网格补 `overflow-x: hidden`，任何越界都不再产生横向滚动条；
  - 网格 / 缩略图的 class 改由 `gridClass()` + `t-attf-class` 统一输出（拖拽态 `is-sorting`、首帧 `is-sorting-init`）。
  - 已核实（对照 `web/static/lib/owl/owl.js` 的 `setClass` / `updateClass`）：Owl 的 `t-att-class` 走 `classList.add/remove`，是 **token 级增删**，不会清掉元素静态 `class`——故本问题与 class 合并无关，真因就是 `!important` 覆盖。
- **排序首帧不再“从左上角飞入”**：排序开始时 position 由 relative 切 absolute、transform 由 `none` 起算，若带过渡会把所有缩略图从网格左上角动画到目标格。现首帧加 `is-sorting-init` 禁用 tile 的 transform 过渡（目标格本就与流内位置重合，视觉完全不动），`onPatched` 后切到 `move` 阶段恢复过渡，保留避让动画。
- **拖拽块贴合鼠标**：按下时记录抓取点在缩略图内的偏移（`grabX/grabY`），拖动时保持该点始终在鼠标下——抓取瞬间不跳位、移动全程贴合；并保留 19.0.2.3.1 的逐帧渲染 + 拖拽块无过渡（松手 `o_gm-snap` 恢复落位动画）。

### 影响

- 仅前端 JS / SCSS / XML 与 manifest 版本；模型 / 字段 / 视图 / 权限未变。
- 交互变化：拖动时缩略图间隙与静态布局一致（无额外间隙、无横向滚动条），抓取与移动全程拖拽块跟手；避让动画与落位动画保留。
